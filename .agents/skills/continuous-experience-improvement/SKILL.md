# 持续改善 UX、DX、AX

在当前仓库和授权范围内，反复交付有证据、范围可控、可验证的改进。每轮完成远程交付后直接进入下一轮；单轮完成不是总目标完成。优先让人和自动化调用方更容易正确完成真实任务，以最小必要复杂度守住正确性、安全、隐私、可访问性、性能与可维护性。

## 适用标准

- **UX**：实际使用或调用是否清楚、省步骤；关键流程、状态反馈、错误恢复、结果可用性和适用的无障碍操作是否可靠。无界面的项目关注调用体验。
- **DX**：开发者能否理解、构建、集成、测试、调试和维护；检查结构、命名、契约、配置、命令、示例与诊断。复用既有机制。
- **AX**：Coding Agent 和自动化调用方能否发现能力、获取上下文、正确调用并验证结果；检查说明、入口、输入输出、成功与失败状态、重试条件和副作用边界。改善 AX 不默认增加 AI 功能、接口或权限。

按适用性选择维度，不机械覆盖三者。已有明确任务时只处理它及直接影响范围；否则审查仓库，建立有证据的优先队列。优先解决正确性和安全问题，其次是阻塞与稳定性、明显的体验或效率问题、维护与自动化障碍。已解决且无新证据的问题不重复处理。

## 启动与恢复

1. 读取项目指令、开发与验证方式；检查工作区、分支、远程、现有修改及未推送提交。记录基线，保护用户已有工作。
2. 确认用户指定或项目约定且已授权的远程工作分支。多个远程目标不明、目标为受保护分支或推送会触发未经授权的生产部署时，先停在需要确认的操作前。遵守项目更严格的 PR、审批和分支规则。
3. 用已有持久状态或运行环境记录简短检查点：轮次、队列、阶段、变更范围、审查与验证、提交哈希、推送状态、阻塞原因。纯执行日志不为凑提交写入仓库。恢复时对照本地与远程真实状态，从未完成阶段继续，避免重复修改、提交或推送。

## 每轮：检查 → 选择 → 实施 → 审查 → 修复复验 → 提交 → 推送 → 确认 → 记录

### 选择与实施

选一个问题或一组紧密相关且可独立验收的改进，记录问题证据、影响、预期结果和验收方法。小步修改，保持既有语义和对外兼容性，除非任务要求改变。只补直接相关的测试和文档；新发现的旁支问题进入队列，阻碍本轮交付或由本轮引入的回归则立即处理。没有实质改进就不制造提交。

### 独立审查

涉及代码行为、配置、依赖或关键接口时，若环境支持且权限允许，至少调用一个独立 SubAgent 只读审查；纯文字等低风险修改可由主 Agent 自审并说明。复杂或高风险变更按需安排 2–3 名审查者，分别关注正确性与安全、测试与 DX/AX、适用的用户流程与可访问性；遵守并发和资源限制。

向审查者提供目标、验收条件、基线、**完整候选差异**和必要上下文，确认其能读到未提交修改。审查期间冻结候选版本。审查者不改实现，不提交、推送、合并或部署；产生文件的测试由主 Agent 执行或在明确隔离的环境执行。要求审查结论注明文件位置、触发条件、影响和证据，并区分阻塞问题、建议与不确定判断。

等待必要审查结束后，主 Agent 复核并去重，修复阻塞问题，说明不采纳的结论。修复后重审、复验受影响范围，旧版本的审查结果不能为新版本背书。环境无法调用 SubAgent 时，明确记录降级自审及独立审查未完成；若项目把独立审查设为强制门禁，则暂停交付。

### 验证与提交

运行与改动匹配的测试、类型检查、静态检查、构建或交互验证；适用时实际走用户流程，性能改进以测量为依据。仅当验收通过、阻塞审查问题解决、必要验证通过、无未处理新增回归时提交。区分既有无关失败与本轮失败；关键验证不可执行时不宣称通过，也不为维持循环推送未经验证的改动。

用户以本目标授权持续交付时，可在**已确认**的远程工作分支常规提交和推送，无需每轮重问；仅加载本技能不扩大授权，运行环境审批和项目限制仍适用。提交前核对完整差异与暂存区，只暂存本轮内容，排除密钥、敏感数据、临时文件和无关产物。形成聚焦、可追溯的提交；提交钩子改动文件后，重新检查并验证最终内容。

推送前核对分支及全部待推送提交。使用普通推送，遵守共享历史与分支保护。远程变化时先比较差异；安全整合后重审、复验受影响范围，不能安全整合则暂停。推送失败或超时先检查远程是否已接收，再有限重试。**确认交付前不进入下一轮，也不积累新的未推送轮次。**

### 确认并继续

读取远程状态，确认目标分支包含本轮提交，并记录提交哈希和分支。若项目把远程 CI 设为门禁，确认对应提交的必要检查通过；失败仍属本轮，修复、补充提交、推送并复查。无法读取必要结果时暂停。推送不代表合并或部署；仅执行另获授权的发布操作。

更新检查点，简要报告改进、审查、验证和远程提交，立即开始下一轮，不在轮次之间询问是否继续。

## 结束或暂停

只有队列清空，且再次检查当前授权范围内适用的 UX、DX、AX 后，没有新的、有证据且值得实施的改进，才报告总目标完成。局部无事可做时检查队列其他区域；全范围无价值改进时停止，不空转。

用户要求停止或调整、资源/时间/轮次上限、无法安全解决的权限/远程/冲突/验证/外部依赖阻塞、连续尝试无实质进展，或后续工作需要未授权的重大变更时，保存检查点并报告**暂停或中断**，不声称总目标完成。说明最后成功提交、本地与远程状态、未完成事项及恢复所需条件。
